## 文件处理规则

- 课程目录内部的子目录和文件名保持不变。
- 个人报告、工程文件、商业教材、电子书和配套音频均保留并上传。
- 以下 3 个超过 GitHub 普通 Git 单文件限制的文件保留在本地，通过精确路径写入根目录 `.gitignore`：
  - `大二/算法设计与分析/算法导论（原书第3版）_13234228.pdf`
  - `大二/计算机组成原理/课程资料/深入理解计算机系统原书第三版.pdf`
  - `大二/数据结构/数据结构基础（C++语言版）第2版.pdf`
- 根目录 `README.md` 提供按学年和课程排列的索引，不提及未上传文件。
- `.git`、`.agents` 等仓库管理目录不参与课程分类。

## Git 工作流

1. 将 `codex/organize-course-resources` 的 Git 基线对齐到 `origin/main`，同时保留当前工作区中的本地课程文件。
2. 以当前本地课程文件为唯一内容来源；远端已有的 8 个计算机组成原理文件不单独保留。
3. 完成目录移动和重命名，并新增根目录 `README.md` 和 `.gitignore`。
4. 验证目录映射、课程内容数量、忽略规则以及待提交文件大小。
5. 创建一个课程资源整理提交。
6. 推送分支并创建以 `main` 为基准的 Draft PR。

## 安全与错误处理

- 移动前检查全部源目录存在、全部目标目录不存在，避免覆盖。
- 所有移动目标必须解析到当前工作区内。
- 对齐 Git 基线前后分别计算本地 `计组` 的文件数量、总字节数和内容摘要；任何差异都必须停止操作。
- 使用保留工作区文件的 Git 基线对齐方式，不检出或覆盖远端课程文件。
- 若仍有超过 100 MB 的待提交普通 Git 文件，停止提交并报告文件清单。
- 若移动后课程目录、文件数量或忽略规则验证失败，停止提交和推送。

## 验收标准

- 根目录课程资源仅通过 `大一`、`大二` 两个学年目录组织。
- 15 门课程全部位于已确认的目标路径。
- 课程目录内部结构和文件名保持不变。
- 本地修改后的 `计组` 内容完整保留，并成为 `大二/计算机组成原理` 的最终内容。
- 分支历史以 `origin/main` 为共同基线，远端原有课程文件由本地整理结果替换。
- 3 个超大文件仍在本地原位置且不会被 Git 跟踪。
- `README.md` 正确列出学年和课程索引，且不提及未上传文件。
- 分支可推送，并能创建面向 `main` 的 Draft PR。
